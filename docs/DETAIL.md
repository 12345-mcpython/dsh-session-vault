# 会话保险箱（会话锁 + 加密导出）

这个插件做三件事，各自独立：

| 能力 | 做什么 | 磁盘上 |
|---|---|---|
| **界面锁** | 侧栏给会话上锁，打开时正文模糊 + 弹口令框 | 不改文件 |
| **磁盘锁** | 上锁时把会话日志加密成 `WALLBK` 密文，DSH 读的时候在内存里解密 | 密文（+ 一个明文 `.header` 元数据旁路） |
| **加密导出** | `session_vault_encrypt` 工具把当前会话打成 `.enc` 备份 | 只读原文件 |

## 为什么「界面锁」是主力

上一版直接加密会话文件，结果会话从侧边栏消失、点开报错。原因很简单：
**DSH 启动要读会话文件才能列出会话**。文件读不出来 = 会话不存在。

所以默认只做界面锁：会话记录照常可读（它必须在），挡住的是「走到电脑前、
能操作 DSH 的人」。要拦「把文件拷走的人」，才开磁盘锁。

## 用法

1. 把鼠标移到侧栏任一会话上 → 点出现的小锁（或右键会话 → 「锁定会话」）。
2. 第一次会要求设口令（至少 6 位）。口令只存 scrypt 派生值，明文不落盘。
3. 之后再打开这个会话：正文模糊 + 一个口令框。输入正确才看得到。
4. 想彻底解开：右键会话 → 「解锁这个会话…」→ 「解锁并永久解除」。

「锁」和「解锁」的区别：

- **解锁**：本进程内放行一段时间（默认 10 分钟无操作后自动重新上锁）。
- **永久解除**：删掉这条会话的锁登记；磁盘锁着的会先把密文解回明文。

## 磁盘锁怎么工作

上锁时把 `session.vN.jsonl.zstd` 原地换成 `WALLBK` 密文，并在旁边写一个
`session.vN.jsonl.zstd.header`，里面是**明文**的会话第一行（id / 创建时间 / cwd）。

为什么要有那个明文旁路：`list()` 必须读到会话头才会把这条会话列出来。
没有它，锁上之后就又会「从侧边栏消失」。所以磁盘锁的取舍是：
**正文是密文，元数据（会话 id、创建时间、工作目录）仍是明文。**

读取时靠 patch `session-persistence-jsonl` 后端的方法在内存里解密，不改磁盘。
细节见 `docs/DESIGN.md`。

## 导出口令（备份）

工具名：`session_vault_encrypt`

| 参数 | 说明 |
|---|---|
| `password` | 必填。加密口令，不会存到任何地方；丢了文件就打不开 |
| `session_id` | 可选。会话 id 或前缀；省略时用当前工作目录下最近改动的会话 |

返回产出文件路径、大小和恢复命令。导出**不改**原文件。

## 配置

在 `cordis.patch.yml` 的 `config` 里改（只在第一次安装时写进 state.json，
之后以插件里的设置为准）：

| 字段 | 默认 | 含义 |
|---|---|---|
| `dest` | `D:\backup\chat` | 导出的 .enc 落点，不存在会自动创建 |
| `keep` | `20` | 保留份数，超出时删最旧的 |
| `autoLockMinutes` | `10` | 空闲多少分钟自动重新上锁（0 = 关） |
| `diskLock` | `true` | 上锁时是否同时加密到磁盘 |

```yaml
- insert:
    - id: dsh-session-vault
      name: '@local/dsh-session-vault'
      config:
        dest: 'E:\mybackup'
        keep: 30
        autoLockMinutes: 15
        diskLock: true
```

## 状态存在哪

`~/.dsh/session-vault/`：

| 文件 | 内容 |
|---|---|
| `state.json`（0600） | 口令哈希、策略、每条会话的锁登记 |
| `session-vault.log` | 插件日志（上锁 / 解锁 / 自动上锁 / 老格式补登） |
| `_diagnostics.json` | 这次进程到底装上了什么：backend-patch 的方法清单、磁盘锁是否可用、两本账的解锁数量 |

「已解锁」不在文件里：它只在内存里，进程一重启就全灭。

## 加密格式

与 wall 项目的 `tools/backup_crypt.py` **完全一致**，两边互相能打开：

```
magic    8 字节    "WALLBK" 0x01 0x00
version  1 字节    0x01
n        4 字节    big-endian，scrypt N（默认 32768）
r        4 字节    big-endian（默认 8）
p        4 字节    big-endian（默认 1）
salt    16 字节
nonce   12 字节
密文     AES-256-GCM 正文 + 16 字节认证 tag
```

AAD 是 `magic || version`。用 GCM 而不是 CBC，是因为它**认证加密**：文件被改动
会解密失败，不会产出看似正常实则损坏的内容。

## 恢复

```powershell
cd K:\wall
python tools\backup_crypt.py decrypt chat-session-xxx.enc session.v4.jsonl.zstd
zstd -d session.v4.jsonl.zstd -o session.jsonl
```

得到纯文本 JSONL，每行一条消息。

## 上一版留下的密文会话

上一版（1.x）把会话文件原地加密但没能让 DSH 读出来，那些会话可能已经在侧栏
消失。本版启动时会扫描会话目录，把「已经是 WALLBK 密文但没登记」的会话补登成
磁盘锁，于是它们重新出现在侧栏（靠的是上一版留下的 `.header`）。

打开它们需要**当初加密时那个口令**（不是任何后来设的口令）；「永久解除」会把它们解回明文。

## 限制

- **界面锁不加密磁盘**：DOM 里仍有文字，挡不住拿文件的人。
- **磁盘锁在写入瞬间会短暂明文**：追加事件时先解、写完立刻重新加密（原子替换）。
- **不要给正在跑的会话上锁**：锁上之后后端会拒绝写入，那一轮会报错。
- **口令没有恢复途径**。这是设计，不是缺陷。
- **改口令会重新加密这条会话的磁盘文件**：先解回明文，再用新盐加密；解不开就拒绝，什么都不改。
